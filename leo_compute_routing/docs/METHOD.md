# 方法：图强化学习卸载、预测图路由与闭式资源分配

本版本完全采用“RL 解决长期去哪算、图算法解决现在怎么走、优化算法解决资源怎么分”的分层方案。

```text
当前 Walker 拓扑 + 有限轨道前视 + 当前任务/工作量
                ↓
     GAT 编码当前节点与边状态
                ↓
     PPO 输出一个计算卫星编号 s
                ↓
   只为这个 s 搜索预测接触感知路径
                ↓
   路由/预测期限检查；失败则明确本地回退
                ↓
   更新同批次预测预约，继续下一任务
                ↓
     完整批次一次性提交真实执行器
                ↓
   KKT 链路/CPU 动态共享，跨时隙服务
```

PPO 对全部卫星节点使用共享评分器，再屏蔽基本不可达节点及可选的独占 CPU 期限下界。路由在节点选择后才执行，不向 PPO 提供路径列表或联合节点—路径动作。路径搜索的内部遍历不等于强化学习的动作空间。

同批任务按 deadline、task ID 顺序决策，预测预约包括当前活动工作与此前选择。预约只用于特征和图路由估计，真实链路和 CPU 仍按共享服务执行。图路由没有找到路径、预测完成超过期限时保留请求节点并本地回退，加入同一代价定义的路由拒绝惩罚；不把拒绝计成实际断链。节点下界 mask 和路由预测均不保证真实成功。

图路由在当前图中搜索跳数受限的无环路径，按实际输入大小检查有限未来接触、参考共享服务时间、窗口余量与链路当前积压。预算耗尽会记录，不宣称精确最优。当前不做跨断链等待、执行中重路由、任务分割或 CPU 迁移。

资源部分保持固定活动集合的 KKT 平方根分配：链路权重为原始输入 bits 的平方根，CPU 权重为原始总 cycles 的平方根。该子问题的最优解不能宣传为动态全局联合最优。

| 对照/消融 | 控制内容 |
|---|---|
| MLP-PPO | 相同动作、路由与分配，只替换图编码器 |
| node_greedy | 相同接触路由、预测预约与资源分配，逐任务选择预测完成最早的节点 |
| snapshot_route | 只用当前容量的路径代价，关闭未来拓扑特征；保留后置期限检查 |
| no_future | 保留同一接触路由代码，将前视 H 置零 |
| no_booking | 不加入同批此前任务的预约，仍保留现有活动任务 |
| no_node_mask | 关闭独占 CPU 期限下界 mask，仍保留结构可达限制与路由后的期限检查 |
| equal | 相同任务、拓扑与资源预算，实际链路/CPU 等分 |

各学习变体独立训练和验证选模；不能把完整方法权重直接切开关当正式学习消融。`node_greedy` 用于判断提升是否确实来自学习，而不仅来自共享图路由和预约。

已删除旧 KSP 联合动作、联合动作特征、旧 Shield 模式和完成时间 logit 先验参数。特征 schema=3；旧 schema=1/2 权重会明确拒绝加载。旧服务器数据保留为历史结果，不能套用新版模型解释。

可讨论的研究贡献是分层通信计算协同、有限接触先验引导路由，以及共享图节点评分的跨规模能力。GAT、PPO、KKT 本身不是新算法；实际长期调度收益和泛化优势需要实验验证。系统模型见 [中文版](SYSTEM_MODEL_ZH.md)、[英文版](SYSTEM_MODEL.md)，运行见 [服务器命令](SERVER_EXPERIMENTS.md)。
