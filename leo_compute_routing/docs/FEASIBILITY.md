# 当前 idea 的可行性分析

分析日期：2026-10-04。依据父目录两份文档，并核对下列论文的公开原文摘要/出版页面；不是穷尽式查新或完整论文复现。

## 判断

**工程上可行，适合按阶段实现；论文创新性需要条件性验证。** 卫星拓扑、K 条候选路由、单卫星完整执行、闭式资源分配都能实现。真正需要验证的是未来信息是否有显著收益，以及学习策略是否超过计算感知强启发式。

先构建可信的仿真和对比平台是正确顺序。只将 GAT、PPO、mask 和 KKT 拼接，不能直接证明新颖性或算法优越性。

## 必须修正或限定的建模问题

### 1. 平方根分配的最优性范围

固定集合和固定工作量时，`min Σ W_i/x_i, Σx_i≤B` 是凸子问题，KKT 给出 `x_i ∝ sqrt(W_i)`。因此文档的链路/CPU 公式本身成立。

但 deadline 的阶跃惩罚不在该凸目标里；未来任务、资源重分配、转发到达时间也不在这个子问题里。不能将这个闭式解称为 P1 的全局最优解，也不能保证它在动态处理器共享下比等分有更小实际平均完成时间。

代码保留平方根与等分两种分配，成员变化时重新分配。消融必须同时检查时延与成功率，允许等分在某些场景更好。

### 2. 计算队列不能提前接收还在传输的数据

文档 `Q(t+1)=[Q(t)-FΔt]^++L_new` 如果把全部卸载任务在决策时计入，会在数据送达前产生 CPU 服务。本版改为：

```text
任务传输中 → 独立在途状态
最后一跳传播完成 → 工作量进入目标 CPU
CPU 实际消耗 → 扣减剩余 cycles
```

准确的工作量守恒应写成：区间结束剩余工作量 = 区间开始剩余工作量 + 区间内真正送达的工作量 - 区间内实际处理的工作量。

当前 CPU 采用处理器共享，`Q/F` 是排空时间/负载代理。不能再把它当严格 FCFS 等待时间加在实际服务时长上，否则会重复计数。若论文坚持原等待项，需要改为明确的排队纪律，并重推队列与 CPU 分配时延。

### 3. 点状到达检查不足以证明路径可行

链路在第一跳开始时存在，不代表它在发送全部输入期间持续存在。代码检查每跳整段传输区间涉及的未来快照；已经发出的数据在传播期间无需继续维持链路。

快照 `k` 覆盖 `[kΔt,(k+1)Δt)`，因此时间到时隙的映射用 floor，而非直接对经过时间用 ceil。恰好在边界前发送完的链路不需要下一快照继续存在。

有限 H 的窗口外信息标为未完全检查；默认允许候选保留，但观测显式暴露 unknown。严格模式可设置 `allow_unverified_future=false`。

### 4. 可行性预测不能忽略共享造成的变慢

本版用参考速率比例做轻量预测。资源竞争可能拉长实际发送时间，使预测通过的路径仍中断。代码的实际执行器会检测这种失败，不把 mask 当作物理保证。

后续研究可以考虑：利用现有链路活动任务数或负载预测速率、加入保守余量、选择后再验证，或对可靠性目标采用机会约束。预测检查所需信息必须与策略实际能获取的状态一致。

### 5. 两个退化点

“只按通信时延选择目标”若包含本地，会永远偏向通信时延为零的本地动作。本版改成明确的 `shortest_offload`：远程候选优先、无路径时本地回退。

“最小 CPU 队列”若负载很低且所有队列为零，会大量并列，效果取决于 tie-break。要明确并列规则，并设置确实存在不均衡负载的场景。

### 6. 原参数可能让未来拓扑收益几乎不可见

0.5–5 Mbit 在 0.5–2 Gbit/s 的独占链路上发送仅约 0.25–10 ms。再加每跳数 ms 量级的传播，路由时间仍常短于轨道接触变化时间。

24 颗、600 km 圆轨道默认场景本次 60 s 产生任务窗口只有 4 次边状态变化。它适合验证跨星计算和负载均衡，但不能预设 look-ahead 一定显著有效。

需要有依据地选择更长的运行窗口、拥塞程度、遥感输入数据量和可用 ISL 带宽，统计真实轨道下基线断链是否出现。合成快速变化的拓扑只用于验证程序逻辑，不能用作现实场景有效性的唯一证据。

### 7. 小星座的连通性与物理遮挡

550–600 km 的轨道不能把任意环形相邻卫星直接相连。例如同一轨道只有 6 颗时，60° 的间隔可能被地球遮挡。本版 24 颗使用 3×8，每轨相邻 45°，仍逐条检查视距与距离，不人为强制连通。

圆轨道、贪心跨轨匹配、无指向/建链延时是第一阶段近似。论文应报告连边规则、连通比例和边变化量；后续有必要再替换为验证过的星座/TLE 与终端规则。

## MDP 和训练可行性

只给 PPO `G(t), Q(t), 当前任务` 在多跳在途任务存在时可能是部分可观测模型。本版额外保留在途/CPU 任务的阶段、固定路径、剩余 bits/cycles、传播剩余时间及 deadline 状态。以后可以编码这些信息，或明确把问题表述为 POMDP。

当前按一个时隙的任务批次统一决策，下层资源由全部活动任务共享。后续 PPO 不能把每个新任务当作互不关联、各自独立推进一个时隙的环境；这会破坏批次竞争与时间模型。建议采用批次因子化动作概率，累加该批次各任务 log probability，并以一个实际时隙作为 GAE 时间步。

延迟完成的任务奖励还需要跨时隙归因。本版提供活动任务数的时间积分作为时延 holding cost，避免奖励只看“本时隙完成的任务”。它等于所有任务驻留时间的累加，但与原“只统计完成任务的均值”目标不同，论文应同步更新定义。

失败惩罚需校准。若迟到时延无界、失败罚款有限，RL 仍可能偏好较快失败；仅提高一个任意系数不能证明消除此风险。后续应明确 deadline 丢弃模型、失败代价或可靠性约束，并始终联合展示成功率。

当前实现假定集中控制器能获得全局状态，尚未包含控制信令、状态过期和分布式资源预约。这是建模假设，不能称为已经实现的星上分布式协议。

## 下一步研究验证顺序

1. 多 seed 验证物理连通性、全局及热点负载比、在途工作量与 CPU 守恒。
2. 在真实轨道场景校准断链条件，验证预测筛选的收益、误拒绝和检查成本。
3. 对比计算感知强启发式、等分资源和有限候选集合的小规模最优参考。
4. 增加候选 MLP-PPO，先确认 reward、GAE、可变候选 mask 与公平回放正确。
5. 再加入 GAT，比较稳定收益和推理开销，并测试跨规模泛化。
6. 至少使用多个训练/评估 seed；报告置信区间，区分训练场景与泛化场景。

如果 GAT 对强启发式没有稳定提升，不应为了维持算法名字而掩盖结果。工程可继续用于分析预测可靠性、资源竞争和复杂度这些实际问题。
