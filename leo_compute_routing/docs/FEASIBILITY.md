# 方案可行性与实现边界

已采用用户指定的三层方案：图 RL 只输出计算节点，后置接触图路由找路径，KKT 分配链路与 CPU。该分工避免 PPO 联合学习离散路径和连续资源，模块可分别验证，工程不需要 Transformer、Lyapunov 或额外优化器依赖。

当前可运行模块包括轨道/接触预测、整任务卸载、变长节点 GAT/MLP-PPO、动态存储转发与处理器共享、固定 seed 回放、预测预约、checkpoint 恢复、对照评估、消融和跨规模入口。实现约定与公式见 [系统模型](SYSTEM_MODEL_ZH.md)。

需要实验检验的核心是长期节点策略能否超越同图路由的当步贪心；三层分工合理不意味着 PPO 必然最优。场景包含本地热点拥塞但全局有余量，以及接触变化；参数假设需公开，低负载控制和强对照都要保留。

路由只在有限前视内检查当前图路径，无跨断链等待和执行中重路由。参考预约不是真实资源锁定，实际速率受未来到达影响，仍可能断链或超期。KKT 最优性限于固定活动集合的静态代理。节点共享评分可变规模运行，但跨规模效果尚须充分训练后验证。

下一阶段优先完成主实验、路由与节点机制消融，再看跨规模与敏感性；暂不增加算法堆叠。旧实现与参数已删除，旧结果作为历史资料保留，新版不能恢复旧联合动作权重。
