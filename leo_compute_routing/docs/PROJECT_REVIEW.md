## 判断与本次改动

最需要先解决的是实验区分度和公平比较。直接训练 PPO，可能只是学习绕开过载热点或同批任务扎堆，不能说明 GAT 或未来拓扑的独立贡献。

本次实现了：

- 默认 CPU 与方案中的 20–100 Gcycles/s 对齐；热点混合概率从 0.7 调至 0.3。该配置作为低负载对照，未经硬件或业务校准。旧参数另存 `configs/legacy_overload.yaml`。
- 48、72 星配置同步扩大热点集合至 6、9 星，避免扩星时热点数量固定、到达率倍增的额外混淆。smoke/contact 合成场景显式保留旧热点概率。
- `evaluation/calibration.py`、`scripts/audit_scenario.py`：审计源概率、逐星/全网计算负载、deadline 乐观下界、通信/计算时间尺度和预测窗口断链可观测性。每次对比自动保存 `calibration.json`。
- `baselines/batch_greedy.py`：按 deadline、task ID 顺序选择，累计 CPU 周期和无向链路 bit 的虚拟预约。提供 `batch_greedy`、`batch_greedy_future`，预约仅影响评分，不改变实际事件进度。
- 固定评估窗口与可选 warmup。利用率在 warmup 后至停止产生任务的固定区间积分；评估任务跟踪至 drain 结束。warmup 任务不进入评估任务分母，但保留其竞争。
- `evaluation/statistics.py`、`scripts/run_multiseed.py`：按 seed 配对，保留逐 seed 原始数据，输出均值、95% percentile bootstrap CI、相对基线的配对差值。重采样单位是 seed。时延存在未定义 seed 时，不静默剔除后给出 CI。入口拒绝覆盖非空结果目录。
- 补充批次竞争、链路预约、窗口裁剪、warmup 竞争、配对统计与保存检查；55 项测试通过。

### 热点负载的正确计算

来源是“以概率 p 在热点集合选，否则在全部 N 星选”，均匀分支仍会选中热点。热点数 H 时，单热点概率为 `p/H + (1-p)/N`，热点总占比为 `p + (1-p)H/N`。

旧配置 N=24、H=3、p=0.7，实际期望热点占比为 **73.75%**。期望到达率 48 tasks/s，独立采样得到 `E[L]=E[D]E[c]=2.75 Gcycles`，单热点每秒到达约 **32.45 Gcycles**。

重建 seed=42 后，三颗热点期望本地负载率约为 **4.95、3.73、3.30**，不是统一的 3.85；全网约 0.701。这里确实存在局部持续过载和资源错配。109 s 的历史时延可以是积压与 drain 的结果，但不能用它与其他策略的差距代表一般收益。

新默认配置保持数据量和到达率不变。即使热点 CPU 取新范围下限 20 Gcycles/s，单热点期望负载率也只有 0.8525；这不保证短时随机批次不会拥塞。seed=42 最大期望局部负载率为 0.375，全网为 0.094，属于低负载。

### 能力单位和通信比例

20–100 Gcycles/s 与方案一致，仍是有效服务能力假设，不能直接等同于物理时钟、多核峰值或 GFLOPS。

[Computing-Aware Routing for LEO Satellite Networks](https://arxiv.org/html/2211.08820v1) 采用 GFLOPS/GFLO 描述能力和任务需求，并研究通信/计算能力变化；它不能直接证明本项目某个 cycles/s 数值真实。正式实验需任务 profiling 的 cycles/bit，或用统一操作数建模任务与服务能力并说明有效利用率。

旧配置四跳参考通信代理约 83 ms，平均 CPU 独占时间代理约 351 ms；新配置后者约 47 ms。这些不是实际四跳路线统计或共享服务时延。

应分别消融 CPU 分配、链路分配、K 条路径和目标节点选择。当前 `resource.allocation` 同时切换 CPU 与链路，**不能独立归因两者**，仍需拆分配置。路由失败为零也不代表链路分配对时延无作用。

至少保留低负载、计算拥塞、通信拥塞三类实验。扫描数据量时同步控制 cycles/bit，可保持计算工作量不变、改变通信需求；扫描到达率、CPU、热点时，应报告逐星负载和实际链路利用率。不能只挑对 proposed 有利的参数。

### deadline 不可行比例

`L/max(F)` 忽略通信、可达性与竞争，是乐观下界。超过 deadline 即全局必然不可行；满足下界却不代表真实可行。

旧 seed=42 的 2801 个任务中，**3 个（约 0.107%）** 违反该下界；若要求本地独占执行则有 78 个违反 deadline。旧配置最坏任务在最快抽样 CPU 上约需 0.640 s。因此问题存在，但整体低成功率不能主要归因于“出生即违约”。新 seed=42 的乐观不可行数为 0。

后续需扫描 deadline 严格程度，并报告下界不可行比例、无竞争候选可行比例。若按服务时间乘 slack 生成相关 deadline，应明确标注为另一种业务假设，保留独立 deadline 对照。

### 预测窗口与批次预约

600 km 圆轨道下，2 s 移动约 0.124°。但临近接触阈值时，很小移动也能改变链路。

当前 60 s Walker 窗口有 4 次无向边状态变化，约 3.33% 的决策窗口存在“当前链路在随后 2 s 内消失”。这不是所选任务实际遇到断链的比例。本次五 seed 的批次基线中，future 没有改变结果。

需延长物理轨道覆盖，报告所选路径在途风险、预测完整覆盖率与参考速率偏差，再扫描 H、时隙粒度和数据量。按快照定位链路变化存在最多一个时隙的边界误差，时隙粒度必须做敏感性分析。`contact_stress` 继续用于功能压力测试，不作为真实轨道收益证据。

新批次基线预约 `(destination, cycles)` 和路径 `(undirected_edge, bits)`，计入当前传输链路工作。已有 CPU 排队及在途工作已包含在候选基础代价中，不重复预约。

工作量/容量是竞争代理，不是处理器共享完成时间的精确预测；下游链路预约也可能偏保守。需验证批次大小、排序和不同负载下的表现。它提供 PPO 的必要强基线，没有证明 PPO 不必要。

正式实验仍需：

- 更多独立测试 seed。五 seed 属于预实验，CI 可能不稳定。seed 同时改变任务与 CPU 抽样；研究纯到达随机性时应固定 CPU 后分层评估。
- 预先确定场景、窗口、主指标；warmup 长度需稳定性诊断，不根据最终排名调参。
- 训练/验证/测试 seed 与拓扑分离，测试集不参与调参。
- 同报成功、失败、删失、分位数和按卫星/链路分解的利用率。当前全网指标会掩盖热点；逐资源容量积分仍待补充。
- 参数来源表区分文献事实、工程假设、校准值与敏感性范围。正式环境确定后冻结依赖，manifest 保存运行版本。
- 保留原始数据。旧结果目录曾清理，旧表只能作为历史记录；本次结果已经重新保存。

## C：核心算法顺序与未完成项

PPO、GAT、训练/测试流程和小规模 Oracle **仍未实现**。环境已有候选 mask 与 fallback，不等于 RL 的 masked policy 已完成。

1. 建立有区分度的实验族和强基线；继续补独立分配消融、逐资源积分和真实接触风险诊断。
2. 小规模有限域 Oracle：6 节点、每批 2–4 个任务，限制候选数，穷举联合动作，用同一引擎评估预定义有限时域目标。明确初始活动任务、后续到达是否已知和 horizon。单批/有限候选搜索不能称全 episode 全局最优；允许未来到达信息时需说明离线参照的信息优势。
3. candidate MLP-PPO：masked categorical、log_prob/entropy、GAE、clip、归一化、检查点与独立测试。同一时隙逐个选择并更新预约，批次完成后只推进一次物理时间。保存每次选择对应的候选和 mask，明确任务选择与批次 reward 的归因。
4. GAT 编码：共用候选、动作头、mask、reward 和训练预算，仅替换状态编码。目标/路径嵌入不能与新增未来信息或候选规则混在一起比较。
5. 正式消融与泛化：分别比较 GAT、future、mask、预约、CPU 分配、链路分配和 K；报告多训练 seed、多测试 seed、学习曲线和完整推理开销。完整决策耗时包括候选构造。

若强基线已接近明确范围内的 Oracle，应收缩 RL 收益主张，或研究更复杂但有业务依据的场景；不能先假定 PPO/GAT 一定更优。
