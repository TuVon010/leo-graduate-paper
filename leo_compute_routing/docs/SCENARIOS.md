# 物理场景与参数说明

完整方法统一为“GAT-PPO 选计算卫星 → 预测接触图路由 → KKT 资源共享”。compute24 与 contact66 是实验场景，不是不同算法。

| 配置 | 用途 |
|---|---|
| `experiments/coupled24.yaml` | 当前优先：24 星中等计算负载、受限通信与高倾角接触 |
| `base.yaml` / `ppo.yaml` | 24 星基础物理参数 / 完整学习参数 |
| `experiments/compute24.yaml` | 24 星、较高计算密度，考察热点计算卸载 |
| `experiments/contact66.yaml` | 66 星、80° 倾角、100 Mbit/s，考察接触变化与通信计算协同 |
| `experiments/contact66_balanced.yaml` | 同轨道与业务类型，提高总到达率的压力点 |
| `experiments/low_load.yaml` | 同基础轨道的低负载控制 |
| `experiments/scale24/48/72/96.yaml` | 同轨道族，按每星任务到达和热点比例缩放，冻结跨规模评估 |
| `smoke.yaml` / `rl_smoke.yaml` | 六节点合成网络，功能检查，不用于真实轨道结论 |

系统数学定义见 [系统模型](SYSTEM_MODEL_ZH.md)，提出方法见 [METHOD.md](METHOD.md)。卫星轨道使用圆轨道 Walker-Delta，当前 ISL 由遮挡、距离、终端度数、跨面纬度及距离排序决定；不保证全部快照连通，也不修改拓扑以偏袒策略。ISL 速率表示分配给该类任务的业务预算，不冒称硬件最大速率。

## 当前 24 星预实验

`coupled24` 继承 `compute24`，仅覆盖以下参数；旧配置和历史结果均保留。

| 参数 | compute24 控制 | coupled24 当前预实验 |
|---|---|---|
| 卫星数 / 高度 | 24 / 600 km | 相同 |
| 倾角 | 53° | 70° |
| 任务业务带宽 | 200 Mbit/s | 100 Mbit/s |
| 到达率 | 16/s | 20/s（5/时隙） |
| 前视窗口 | 4 s（16 时隙） | 8 s（32 时隙） |
| 奖励归一化 | 4 | 5，与到达率同步 |
| CPU / 数据量 / 计算密度 / 期限 / 热点 | 原参数 | 全部相同 |
| 采样 / PPO 更新设备 | 与训练设备相同 | CPU 顺序采样 / 自动选择 GPU 更新 |
| 训练回合数据 | 原固定回放 | 单根 seed、不同回合任务/CPU/热点/轨道起始时刻 |

原固定回放、参考轨道历元下，2026/100 的审计全局计算负载分别约 0.709/0.732，600 s 全程连通，平均约 30 条无向边。70° 并没有增加该时域的链路切换总数（仍为 20 次），主要使连接更稀疏；降低带宽后，参考 4 跳网络耗时约 3.27 s，通信已与计算同量级。不能将该场景直接声称为“高频断链”。80° 的 24 星变体仅约 66.5% 时隙连通，因此没有用作当前主预实验。

当前 coupled24 开启回合随机化：根 seed 2026 保持固定，回合初始时刻在一个完整轨道周期内均匀抽取；CPU、任务与热点身份分别重采样，CPU 在本回合内固定，热点数量、混合概率及其他物理参数不变。不同算法使用同编号的同一场景，不按连通性或性能重抽场景。前 6 回合审计的全局期望负载约 0.663–0.805，6 段 600 s 时域全部连通；这是有限样本审计，不保证所有后续回合连通。保存于 `results/randomized_episode_audit_20261009.json`。

seed 100 均匀抽取 64 个任务的空系统路由审计中，803 个可达远程目的节点的快照路径约 0.75% 跨越失效接触。这是路径暴露诊断，不是实际任务断链率；未来预测贡献仍需 no_future/snapshot_route 消融验证。该场景没有按 GAT 与基线排名筛选，不能保证 GAT 优于 MLP。

GAT、MLP 和所有基线使用相同物理配置、任务与 CPU 回放。MLP 继承节点 mask、接触路由、预约和 KKT，应标为图编码消融。

服务器完整 600 s 回放的 seed 100 预检查中，计算感知启发式成功率为 93.23%，同路由/预约的 node_greedy 为 95.35%，均无截尾。这说明该负载下存在较好的可执行调度，而成功率没有完全饱和；当前将 100 Mbit/s 点固定为第一轮 40 updates 的预实验配置。参数没有根据 GAT 是否获胜筛选。

此前固定回放协议下，冷启动各 1 update 的 GAT/MLP 验证成功率仅约 49.48%/50.38%，远程请求拒绝约 77.51%/89.05%，源星队列堆积明显。随机动作训练回放成功率约 66%，与确定性验证不同。这些不是新回合随机化协议的效果结论；40 updates 后应同时检查验证代价、拒绝率、截尾与队列。如果拒绝长期不下降，应先诊断节点策略和价值学习，再决定是否增加训练量。

## 负载解释与接触审计

热点来自混合分布：每星源概率为 `(1-p_h)/S + p_h/H`（热点）或 `(1-p_h)/S`（非热点）。compute24 的 3 颗热点实际承接约 30% 任务；典型每颗 CPU 70 Gcycles/s 时，热点本地负载约 1.37，全局约 .57。因此本地热点可能拥塞而全局仍有余量，卸载有合理动机。此前“3×70 Gcycles/s = 2.1e12”的计算错了一位；正确是 2.1e11。

contact66 的典型全局负载约 .38；热点单星约 .94，具体依 seed 的异构 CPU 而变。`contact66_balanced` 提高到达率至每时隙 18，典型全局约 .62、热点约 1.54，可用于压力敏感性，而不是看到不利结果后替换主场景。低负载即使成功率饱和，也应保留作为控制。

轨道前视不是未来任务先验。策略与路由只能读取 H=16 的未来快照；发送区间不完全覆盖则默认拒绝远程路由。链路变化频率和策略真正经过断链边的频率应分开审计。参考预测、空系统审计不等于实际实现时延。

## 回放、统计与代码对应

当前训练初始化与场景根 seed 固定为 2026，各回合使用独立派生的数据；验证与开发比较仍使用单一 seed 100 和参考历元。验证复用不叫独立测试，单 seed 不产生置信区间。完成任务均值/P95 与成功、实际断链、路由拒绝和截尾共同报告，指标口径见 [EXPERIMENTS.md](EXPERIMENTS.md)。

| 模型部分 | 当前实现（相对于 src/leo_routing） |
|---|---|
| 轨道与外生 ISL | topology/walker.py、topology/graph_builder.py、topology/topology_cache.py |
| 任务与异构 CPU | tasks/task_generator.py、env/leo_env.py |
| 节点选择与图编码 | models/destination_scorer.py、models/gat_encoder.py、agents/ppo_agent.py |
| 有限接触与选定节点路由 | network/contact_plan.py、routing/contact_aware_router.py |
| 预测预约 | routing/reservations.py |

| KKT 资源共享 | resource/cpu_allocator.py、resource/link_allocator.py |
| 系统成本与评估指标 | env/reward.py、env/metrics.py |
